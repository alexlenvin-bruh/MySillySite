What KSC Is and What to Do with It

21 July 2026 #kaspersky#enterprise#sysadmin

If you have ever installed antivirus software on your home computer, you know the drill: download it, install it, and let it update, scan, and remove malware on its own. You hardly ever need to touch the settings. Once a year, you might check whether it is still alive, and that is about it.

Now imagine that you do not have one computer but a thousand. Or five thousand. Or, as in my case… a lot. They are scattered across offices, cities, subnets, and remote employees' laptops. Running around with a flash drive to install Kaspersky by hand? That sounds rather impossible. And how are you supposed to keep track of every machine?

This is where KSC — Kaspersky Security Center — comes in. It is a centralised security management system: you can monitor managed hosts, install things on them, change things, forbid things, and do it all from a single console.

Meet the Cast

KSC (Kaspersky Security Center)

This is the central component. Traditionally, it is installed on Windows Server, although the vendor is now moving towards Linux, including Astra Linux (import substitution and all that). KSC stores:

  • A database — information about every host, its status, events, and incidents.
  • Policies — the rules that govern antivirus software on managed hosts.
  • Tasks — what to do and when: scan, update, or install patches.
  • Installation packages — KES distributions delivered to clients by KSC.
  • Reports — pretty (and not-so-pretty) tables for management, among other people.

KES (Kaspersky Endpoint Security)

This is the client side: the antivirus software installed on a workstation or server. KES is the familiar “antivirus” in the traditional sense — file monitoring, scanning, heuristics, network protection, device control, and so on.

KES on its own, however, does not know what you expect from it. Its behaviour depends on the licence key, the system it reports to — KSC or Kaspersky Anti Targeted Attack — and the policies assigned by the administration server.

Network Agent (Security Center Agent)

This is a small application installed on every host. It provides communication between KES and KSC.

How It All Works Together

The whole system follows a simple principle: centralised management, distributed execution.

KSC runs on a dedicated server, but distribution points can — and should — be created as well. KSC becomes the single management point for the entire antivirus infrastructure, while distribution points help it do the job.

Network Agents are installed on target hosts. They provide two-way communication: they receive policies and tasks from KSC, then send statuses, events, and execution results back.

KES is installed alongside or on top of the agent and performs the actual protection: monitoring the file system and network traffic, controlling devices and applications. Its settings come from KSC through the agent.

For remote branches or isolated network segments, distribution points are deployed as local nodes that cache database updates and installation packages. This reduces the load on network links and speeds up content delivery.

Policies and tasks are assigned not to individual hosts but to administration groups — logical collections of machines. This makes bulk management possible: change a policy once, and it is applied to hundreds of hosts.

Why Bother When You Can “Just Install Antivirus”?

On a home computer, you can. In an enterprise, not so much:

Without KSC With KSC
Every host must be managed separately Everything can be managed from one console
No clear view of where an outbreak is happening Incidents are visible in real time
Every machine updates however it can Updates are managed centrally
Security policies exist mostly in theory Policies are enforced and monitored
USB drives are the users' sacred right USB access can be disabled across the estate in five minutes

And Who Is KICS?

Kaspersky Industrial CyberSecurity is a separate product designed to protect industrial networks: ICS, SCADA, and PLC environments. While KES protects ordinary Windows machines, KICS works with systems you cannot simply poke at, because doing so might stop an entire factory.

The basic architecture is similar: a management centre, agents on hosts, and policies. The hosts, however, are not office PCs but data collection servers, operator workstations, and network gateways. The stability requirements are on another level entirely.

A Few Terms You Will Encounter

  • Policy — a set of KES settings. One policy is essentially one antivirus behaviour profile.
  • Task — a one-off or recurring action, such as scanning drive C: or updating databases.
  • Administration group — a logical collection of hosts, useful for applying policies in bulk.
  • Distribution point — a local server in a branch or subnet. It caches updates, distributes them to hosts, and relays policies so that every laptop does not have to download databases from the internet.
  • Event / incident — anything that happened on a host and that KES considered worth reporting, from “malware detected” to “a user plugged in a flash drive.”

In Short

KSC is an infrastructure tool that lets you manage security across hundreds or thousands of hosts without losing your mind. KES is the workhorse on each machine. The agent ties them together. Together, they turn chaos into a more or less manageable process.
